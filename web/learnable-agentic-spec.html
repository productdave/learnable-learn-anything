Product specification - June 25, 2026

Learnable is an agent you talk to, not a SaaS dashboard you manage.

Learnable turns a learner's intent, context, files, links, notes, and feedback into a complete course. It does this through a visible agent workflow: collect context, design curriculum, ask for human approval, research, ask for human approval again, write lessons and practice, then review and publish the course.

Core promise Create a course with the learner, not for the learner in a black box.
Primary interface A workflow agent with human checkpoints and context intake.
Technical spine OpenAI Agents SDK for orchestration, tools, handoffs, guardrails, state, and tracing.

What Learnable Does

A course creation agent for serious self-directed learning.

Learnable helps someone go from "I want to learn this" to a usable, personal course. It is not trying to be a marketplace, corporate LMS, creator platform, or generic content generator. It is an agentic learning system that asks for context, makes judgment calls, shows its intermediate work, and lets the human steer before expensive lesson generation begins.

For the learner

Say what you want to learn, add any context you already have, approve the direction, then study a course that fits your goal and starting point.

For the agent

Coordinate specialist sub-agents, preserve source context, expose decisions, and produce structured course artifacts.

For the product

Make the creation process legible. The user should always know which agent is working and when their feedback matters.

Positioning: Learnable is "ChatGPT for building and taking a course," but with an explicit workflow, durable course artifacts, and review gates before the agent commits to the full build.

Core Workflow

The learner and the agent co-create the course.

1

Context intake

The learner gives the topic, goal, current level, desired depth, files, pasted notes, URLs, constraints, examples, and "do not cover" guidance.

Human input
2

Curriculum design

The Curriculum Designer proposes the course scope, module sequence, topic map, prerequisites, outcomes, and expected difficulty.

Agent work
3

Curriculum review checkpoint

The learner approves, edits, or rejects the direction. Feedback is folded into the next design pass before research starts.

Human approval
4

Research pass

The Researcher grounds each module in sources, examples, key concepts, misconceptions, practical use cases, and diagrams worth creating.

Agent work
5

Research review checkpoint

The learner verifies the source direction, asks for more depth, removes irrelevant branches, and adds more context before lessons are written.

Human approval
6

Lesson and practice creation

The Lesson Writer and Practice Designer produce explanations, examples, quizzes, exercises, flashcards, summaries, and optional projects.

Agent work
7

Review and publish

The Reviewer checks consistency, missing assets, factual risk, level fit, quiz alignment, and course navigation before saving a version.

Agent work
8

Learn and iterate

The learner studies the course, asks the Tutor for help, and can ask Learnable to revise sections based on confusion or new goals.

Human plus agent

Agent System

Specialists with one orchestrator, not five unrelated prompts.

Learnable should use one Course Orchestrator as the visible agent. The learner talks to this agent. Behind it, specialist agents are invoked through handoffs or agent-as-tool calls depending on whether the conversation should move to the specialist or simply ask the specialist for a structured artifact.

Course Orchestrator
Owns the run state, decides the next step, routes to specialists, streams progress to the UI, asks for human approval, and resolves conflicts between agents.
Context Intake Agent
Converts raw user input, files, URLs, notes, and constraints into a normalized learning brief. It should ask follow-up questions only when missing information would materially change the course.
Curriculum Designer
Creates modules, sequence, outcomes, topic boundaries, difficulty curve, prerequisites, and assessment strategy. It should optimize for learnability, not just coverage.
Researcher
Produces source-backed research bundles: key concepts, examples, misconceptions, diagrams, source notes, and open questions for the learner to approve.
Lesson Writer
Writes each lesson with a deliberate arc: why it matters, explanation, concrete example, common mistake, recap, and next step.
Practice Designer
Creates quizzes, exercises, flashcards, prompts, and projects that test what was just taught. It should mix recall, application, and transfer.
Reviewer
Checks coherence, source coverage, duplicate topics, missing practice, hallucination risk, tone, and whether lessons meet the original goal.
Learning Tutor
Runs after the course exists. It answers questions using the course content, adjusts explanations to the learner, and can request course updates when confusion repeats.

OpenAI Agents SDK Design

Use the SDK for orchestration, approvals, tools, state, and observability.

OpenAI positions the Agents SDK for apps that plan, use tools, collaborate across specialists, and maintain enough state for multi-step work. That maps cleanly to Learnable because course generation is not one prompt. It is a run with source ingestion, specialist work, approval interruptions, and final artifact assembly.

Data Model

Everything important becomes a durable artifact.

The product should not rely on an invisible chat transcript. Each stage should produce structured outputs that can be reviewed, revised, traced, tested, and reused.

Object Purpose Important Fields Created By
LearningBrief Normalized user intent and context. topic, goal, learner_level, depth, constraints, source_assets, success_criteria Context Intake Agent
SourceAsset Files, URLs, notes, transcripts, or pasted material. type, title, content_ref, extracted_text, metadata, trust_level Ingestion tools
CoursePlan Reviewable curriculum before research and writing. title, promise, modules, topics, outcomes, prerequisites, exclusions Curriculum Designer
HumanFeedback Approval notes and requested changes at checkpoints. checkpoint, decision, notes, requested_changes, timestamp Learner
ResearchBundle Module-level grounding for the lesson writer. key_concepts, examples, misconceptions, source_notes, diagram_ideas Researcher
Lesson Course unit learners actually study. title, objective, explanation, example, misconception, recap, references Lesson Writer
PracticeSet Learning checks tied to lesson objectives. quiz_items, exercises, flashcards, projects, answer_keys Practice Designer
ReviewReport Final quality gate before publish. issues, fixes_applied, residual_risks, quality_score, publish_decision Reviewer
CourseVersion Immutable saved course snapshot. course_id, version, plan, lessons, practice, sources, review_report Orchestrator

UI Specification

The interface should show the workflow before the course.

Home screen

  • Workflow cards are the primary surface.
  • "New course" and "Add context" open the same intake flow.
  • Active runs show exactly which step needs human input.
  • Recent courses sit below the workflow, not above it.

Context intake

  • Topic or question.
  • Goal and reason for learning.
  • Current level and desired depth.
  • Files, URLs, pasted text, notes, examples, and constraints.

Checkpoint review

  • Show the artifact, not just a status message.
  • Use "Approve" and "Revise" as the main actions.
  • Give the learner one feedback box with examples of useful feedback.
  • Preserve all checkpoint decisions in the course history.

Course player

  • Sidebar module navigation.
  • Lesson content, quiz, flashcards, and exercises in one flow.
  • Tutor answers only from course content and approved sources unless asked to expand.
  • Confusion signals can trigger revisions.

Requirements

What must be true for Learnable to feel like Learnable.

Functional requirements
  • Create a course from a short prompt.
  • Create a course from rich context, including files, URLs, and pasted notes.
  • Pause for human review after curriculum design.
  • Pause for human review after research.
  • Regenerate curriculum or research from feedback.
  • Generate lessons, quizzes, exercises, flashcards, and summaries.
  • Save generated courses as versioned artifacts.
  • Resume interrupted runs from checkpoints.
Quality requirements
  • The course must match the stated learner level and goal.
  • Every topic must have at least one learning objective.
  • Every lesson must include practice.
  • Research-backed claims should preserve source references.
  • The reviewer must flag weak source coverage, duplicated topics, and unsupported claims.
Safety and trust requirements
  • Tell the learner when source extraction fails.
  • Never silently ignore user-provided context.
  • Show what changed after feedback.
  • Separate generated conclusions from quoted source material.
  • Use guardrails for unsafe requests, copyrighted source handling, and medical/legal/financial learning topics.
Non-goals
  • No SaaS admin dashboard as the core product.
  • No public course marketplace in the first version.
  • No instructor analytics suite before the learner loop is excellent.
  • No opaque one-click "generate everything" as the default for serious courses.

Build Roadmap

Start with the smallest agentic loop that proves the product.

MVP: visible course creation workflow

  • Workflow home screen.
  • Context intake with topic, pasted text, URLs, and files.
  • Curriculum Designer with human review.
  • Researcher with human review.
  • Lesson Writer, Practice Designer, and Reviewer producing a saved local course.
  • Basic tracing and run logs for every generation.

V1: durable agent runs

  • Server-side run persistence.
  • Resume after browser close or network interruption.
  • Course version history.
  • Structured source library per course.
  • Quality evals for common course briefs.

V2: adaptive learning loop

  • Tutor uses learner progress and confusion signals.
  • Course revisions from repeated missed questions.
  • Spaced repetition queue.
  • Personal learning memory across courses.
  • Optional voice tutor for lesson review.

Later: collaboration and publishing

  • Share a course with a friend or cohort.
  • Export to PDF, Markdown, slides, or LMS formats.
  • Instructor mode.
  • Team knowledge-base courses.
  • Public course publishing only if the learner product is already strong.
